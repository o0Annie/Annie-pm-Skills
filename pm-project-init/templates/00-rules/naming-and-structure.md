# 目录职责与命名约定

## 目录职责

| 目录 | 放什么 | 不放什么 |
| --- | --- | --- |
| `00-rules/` | 规则和模板 | 具体需求内容 |
| `01-inputs/` | 原始输入（讨论、文档、截图、外部材料） | 改写后的结论 |
| `02-product/` | 稳定产品事实（术语、背景、平台基线） | 未确认的方案 |
| `03-planning/` | 跨需求规划（问题空间、模块地图、决策记录） | 单个需求的细节 |
| `04-requirement-pool/` | 需求池（候选需求登记和状态跟踪） | 需求详细定义 |
| `05-requirements/` | 单需求工作包（每个需求一个子目录） | 跨需求规划 |
| `06-versions/` | 版本管理（目标、范围、里程碑） | 需求状态 |
| `07-reviews/` | 评审、验收、复盘 | 原始输入 |
| `90-assets/` | 共享资产（演示、原型截图等） | 事实性结论 |
| `99-archive/` | 已关闭或过期的材料 | 仍在使用的材料 |

编号前缀的作用：文件管理器里按名称排序时，就是工作流的自然顺序。

## 命名约定

- Markdown 文件：英文小写 kebab-case（`problem-space.md`、`decision-log.md`）
- 日期材料：`YYYY-MM-DD-<主题>`
- 需求目录：`req-<四位编号>-<英文短名称>`（如 `req-0001-route-management`）
- 版本目录：`v<主版本>.<次版本>`
