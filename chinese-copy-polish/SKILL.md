# 中文文案润色

把「内容正确但读着别扭」的中文文案，改成「像中国人给中国人写的」。**只优化表达，不改动事实、不新增信息、不删除功能点。**

## 工作流

分三步走，不要跳过第一步直接重写：

1. **先诊断**：通读原文，指出**最主要的 2–4 类问题**（各配一处原文例子），让用户看到「为什么读着别扭」。不要一上来就贴改写稿。
2. **再改写**：逐段润色，覆盖原文所有信息点。改写时对照 `references/rules.md` 的规则清单。**润色手册 / 使用指南类文档时**，额外套用第 7 节的手册专项：操作小节用「如果你想…」场景视角开头、陪伴式语气（去冷命令 / 去俚语 / 焦虑处加关怀）、路径用 ➔、提示与权益用 `> 💡` 引述块分离、交织逻辑拆成平行分支。
3. **后自检**：改完运行 `python3 scripts/check_zh.py <文件>` 做机械体检（中英文空格、全角标点、破折号、emoji 密度、超长句），按提示修正；再人工确认「结论是否前置、长句是否已拆、翻译腔是否清除」。

## 七条核心原则（速记）

1. **结论先行**：先说「能得到什么 / 能干什么」，再说「怎么做」。别让读者读到最后才明白重点。
2. **短句为主**：一句话一个意思。超过 40 字先想能不能拆。名词堆砌改成「动词 + 对象」。
3. **去翻译腔**：删「进行 / 对……进行 / 基于 / 通过……的方式 / 众所周知」等虚词套路；被动改主动；「的地得」不啰嗦。
4. **克制装饰**：加粗只留真正的关键词；emoji 每节最多一个、能不用就不用；不用破折号 `——` 串句，改用句号或冒号。
5. **说人话**：用读者会说的词，不用产品/运营黑话（如「赋能」「抓手」「心智」「场景化」）。
6. **排版规范**：中英文 / 中文与数字之间加空格；中文语境用全角标点（，。：；「」），不混半角。
7. **标题干净**：章节标题只用名词或目标短语，不塞口语旁白或括号解释（「快速上手（第一次使用，跟着走一遍）」→「快速上手」）；解释性的话放到标题下面的正文。

> 详细规则、每条的「病例 → 改写」对照、以及常见翻译腔词表，见 [`references/rules.md`](references/rules.md)。改写前若拿不准某类问题怎么改，先读它。

## 边界

- **不碰事实**：数字、流程、功能、状态、术语一律照原文，拿不准就保留并向用户标注。
- **不做扩写**：不为「更丰满」而新增卖点或步骤；这是润色，不是创作。
- **保留结构**：除非用户要求，不重排章节层级（那是结构重排，属另一件事）。
- **尊重既定规范**：若项目已有语气 / 术语约定，以项目约定优先。
